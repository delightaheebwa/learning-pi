### [MEDIUM] State-gate "blocking" degrades to UNVERIFIED after the retry cap — contract overstates the guarantee
- Where: `.pi/extensions/learning-gate/gate-core/engine.ts:877` (legacy path), `:1305` (judge path); `contracts/learning-core.json:193-200`, `CONTRACT.md:133-138`
- Evidence: both cap paths only withhold-at-cap for `claims` turns with hard facts (`tag === "claims"`, legacy `:922`; `turnType === "claims"`, judge `:1410`). A close summary is `[[TURN:none]]`, so a persistent `STATE_AUDIT_ERRORS` withholds twice, then renders anyway with `⛔ UNVERIFIED` — the exact banner-blind delivery the audit's F7 warns about. The golden tests (`golden_test.mjs:211-225`) assert only the first withhold, never the cap behavior.
- Why it matters: the contract promises errors "block the summary … until the drift is fixed and the audit re-runs clean." In practice any persistent error (including an audit bug, which by definition the Tutor cannot fix) leaks through after 2 retries — the Tutor's normal withhold→re-emit loop trips the cap by itself. "Blocking" is really "delay twice, then show."
- Recommended fix: either amend the `G-state-audit-blocking` statement to disclose the cap degradation ("withholds, subject to the standard retry cap, after which it degrades to UNVERIFIED"), or exempt `STATE_AUDIT_ERRORS` from the cap for `none` close summaries and document the manual escape hatch. Do not leave contract and implementation disagreeing.

### [MEDIUM] Demotion whitelist still matches bare keywords, so a content location can be demoted
- Where: `.pi/extensions/learning-gate/gate-core/primitives.ts:798-800` (`BOOKKEEPING_PATH_RE`)
- Evidence: the regex matches bare words (`provenance`, `staged files`, `worktree`, `git history`, `commit message`), not just paths. Probes: `location: "Knowledge Wiki/wiki/Backprop.md provenance marker missing"` → `reviewIssuesAllOutOfScope` returns `true` (demoted) although it cites a content page; `location: "Knowledge Wiki/wiki/X.md"` + issue mentioning `attempts.json` → correctly not demoted. The brief required "a finding that cites a content location can **never** be demoted."
- Why it matters: low likelihood (verifiers usually cite clean paths), but the finding the audit feared (F12 — a real content defect shipped as flags) is still constructible through exactly this word, and "provenance marker" findings are plausible now that P0.6 made provenance load-bearing.
- Recommended fix: anchor the whitelist to path-shaped locations (require a `/`, `.md`/`.json` suffix, or known state-dir prefix) instead of bare-substring matching, and add a gate test with a content path that embeds a bookkeeping word.

### [MEDIUM] Review-close half of the state gate has no test
- Where: `test/golden/golden_test.mjs:198-225`, `.pi/extensions/learning-gate/gate-core/engine.ts:555-556`
- Evidence: both `G-state-audit-blocking` tests use `[[FLOW:ingest]]`. The review-close branch (`run.flow === "review" && run.reviewSessionWrote && P.looksLikeReviewSummary(text)`) is a second, distinct condition with its own fuzzy matcher (`REVIEW_SUMMARY_RE` matches any message containing "next review"), and nothing exercises it. `learn-check` passes because the test-name substrings match, not because both branches are covered.
- Why it matters: the review close is where the audit's state-drift history actually lives (re-dated review records); an untested branch with a broad summary-matcher risks both false passes and false blocks.
- Recommended fix: add one golden test driving `[[FLOW:review]]` through `review-clerk` + `review-session-audit` with `errors:1` (expect `STATE_AUDIT_ERRORS`) and one with warnings (expect banner).

### [MEDIUM] Scout TTL is a prompt instruction, not enforcement — stale-digest teaching is not prevented
- Where: `.pi/skills/learning-teach/SKILL.md:147`, `.pi/skills/learning-system/SKILL.md:48`, `pi/audit_state.py:437-469`
- Evidence: the 7-day TTL rule lives only in skill prose ("must be re-scouted … never treat a stale digest's source excerpts as authoritative"). `audit_state.py:462-466` reports a stale digest as `warn` (non-blocking by design), and no gate checks digest age (contrast `G-scout-required`, which withholds teaching with zero scout context). The exact F10 occurrence (13-day-old digest taught from) would still flow if the Tutor skips the instruction.
- Why it matters: the brief asked to "require a re-scout … Prefer a hard requirement for new material"; what landed is advisory text the model may ignore, with the audit deliberately kept at warn-level so it can never bite.
- Recommended fix: keep the warn at ingest close (the roadmap's retroactivity concern is valid), but add a teaching-time check the model cannot skip — e.g. surface digest age in the scout-digest gate note and withhold `claims` on a STALE digest for new lessons, or promote TTL-exceeded to an audit error only when the digest is consumed for *new* material. At minimum, record this as a known gap instead of "Enforce Scout TTL."

### [MEDIUM] `ops.py amend` accepts semantically invalid values (negative hints, far-future re-date)
- Where: `learning-system/scripts/ops.py` (`do_amend`, hints branch + `new_date` handling)
- Evidence: `--field hints --value -3` → `AMEND OK: hints: 0 → -3`; `--new-date 2099-01-01` → accepted, `next_review 2099-01-08` (concept hidden from SRS for 73 years). Correctness edits and malformed dates are correctly rejected (exit 2), and `--reason` is enforced — the validation frame is there, these cases just aren't in it. Covered tests (`TestAmend`: re-date, metadata fix, missing reason, unknown field, missing attempt) don't probe value ranges.
- Why it matters: `amend` is now the *only* sanctioned correction path; a typo'd negative hint count silently corrupts the hint-debt/independence telemetry P0.4–P1.9 depend on, and a typo'd year silently removes a concept from review.
- Recommended fix: reject `hints < 0`, reject `--new-date` in the future (or beyond a small skew window) with exit 2, and add both cases to `TestAmend`.

### [LOW] `looksLikeIngestSummary` arms the state gate on any message mentioning "state audit" / "files written"
- Where: `.pi/extensions/learning-gate/gate-core/primitives.ts:708-712`
- Evidence: `INGEST_SUMMARY_RE` matches substrings (`state audit`, `files written`, …) in any post-`clerkCalled` message, so a mid-flow status note ("files written so far: …") with outstanding errors is withheld as `STATE_AUDIT_ERRORS`, not just the close summary. Pre-existing pattern (the review-gate close had the same shape), narrowed in practice because it only fires after the clerk run.
- Why it matters: false-block risk on ordinary post-clerk messages; the remedy text tells the Tutor to fix audit errors for a message that isn't the close.
- Recommended fix: require the `STATE_AUDIT_VERDICT` marker (which the clerk actually emits) rather than bare substrings, for the ingest-close arm.

## Verdict

P2 does what the roadmap claims, with the soft spots concentrated where P2 chose prose over mechanism: the state gate blocks once but leaks at the retry cap (and the contract doesn't say so), Scout TTL is an instruction no gate checks, and the demotion whitelist still demotes on bare keywords like "provenance." Nothing is broken outright — both `learn-check` and the 48 `ops_test.py` tests pass, the contradictions are genuinely gone, `amend` correctly refuses correctness edits, and the pi-canonical freeze is bannered everywhere it should be. The single most important fix is M1: reconcile the `G-state-audit-blocking` contract with the retry-cap reality (disclose the degradation or exempt the close summary), because a blocking guarantee the implementation doesn't keep is worse than an honest soft-block.
