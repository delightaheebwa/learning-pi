[[FLOW:review]]
Run a review session. Load the `learning-system` skill and follow its Review flow.

First call the `review-scout` subagent to gather the review context and build the due queue, then run the review from its digest — do not gather state yourself. The digest's `queue` is computed deterministically (`ops.py queue`) and is authoritative: use it verbatim, do not rebuild, re-sort, or re-derive it, and write each question from that entry's `question_type` + `source_excerpt`. Ask the whole queue in one message. Before emitting it, dispatch ONE foreground `quiz-audit` whose envelope carries `questions_json` (the structured items) AND `rendered_content` = the **exact full batch text** you will render (intro/instructions + every question + its options), then emit that text unchanged — the gate binds on 100% coverage, so a questions-only envelope strands the turn as `QUIZ_AUDIT_STALE`. Derive the active track and current position from `Learning System/CURRICULUM.md` and `Learning System/MISSION.md`; if they disagree, stop and report. Verify every grade with a foreground `grade-audit` subagent — do not bypass the gate — and when one learner reply answers several questions, send ONE batched `grade-audit` envelope with an `items[]` entry per answer (never one subagent call per answer; the harness rejects more than one subagent call per turn).

Context discipline (keep the session light): never dump a full `git diff` — use `git diff --stat` (or `--numstat`) and only `git diff -- <path>` for a file you actually need; read state/wiki files by section (`python3 scripts/ops.py bundle "PATH@^## "`), never re-read a file already in context; keep the audit report to its verdict line plus any ❌/⚠️. Do not switch the model mid-review. Cap the review at 5 grades and end the flow when done rather than continuing into unrelated work.

You do NOT write state files. At the close, hand the durable writes to ONE foreground `review-clerk` subagent (`Reviews/` note(s), session note, touched Active Concepts / Mistakes rows, Attempts sync, state audit, commit) as a `REVIEW_WRITES` JSON-string envelope carrying the exact transcript and verifier verdicts (`task` is a JSON **string** — a quoted literal holding the envelope with its inner quotes escaped, never a nested object; if pi-subagents rejects it with `task: must be string`, re-emit the *same* envelope as a quoted string, do not rebuild it). Fold its `REVIEW_CLERK_WRITES` receipt and `STATE_AUDIT_VERDICT`.

Then dispatch ONE foreground `review-session-audit` on the exact writes before the closing summary:
`subagent({ agent: "review-session-audit", task: '{"gate":"review_session","concepts":[...],"transcript":"exact Q/A + learner answers + verifier verdicts","grade_verdicts":[{"concept":..,"correct_verdict":"pass|fail"}],"written_files":[{"path":"Learning System/Reviews/...","content":"exact written text"}],"state_rows":"..."}', async: false })` (`task` is a JSON **string** — a quoted literal holding the envelope with its inner quotes escaped, never a nested object; if pi-subagents rejects it with `task: must be string`, re-emit the *same* envelope as a quoted string, do not rebuild it). `written_files` may name paths only — the auditor reads the files on disk.
A `PASS`/`PASS_WITH_FLAGS` renders clean; `ISSUES` renders with a `⚠️ REVIEW FLAGS SURFACED` banner (never a withhold, never a re-run — cap 2 passes). Scope is fenced: state drift the review did not write is `context_notes`, never a blocking issue.

Begin every assistant message with a turn tag on its first line — `[[TURN:claims]]`, `[[TURN:quiz]]`, `[[TURN:grade]]`, `[[TURN:viz]]`, or `[[TURN:none]]`. A viz request during a review is parked until grading is done. The gate strips the tag before the learner sees it. It also infers a `grade`/`quiz` turn when you forget the tag but the matching `grade-audit`/`quiz-audit` receipt binds the emitted text, infers `claims` when a `fact-check` draft covers the text, and treats an untagged closing summary as an implicit `[[TURN:none]]` once the review-session audit receipt is present — so a dropped tag no longer dead-ends the review. An unverified or unbound message is still withheld. Dispatch each verifier once, foreground (`async: false`); never re-dispatch the same draft — re-emit the verified text or fix the tag.
