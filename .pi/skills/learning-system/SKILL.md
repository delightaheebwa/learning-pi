# Learning System

The active learning system, running in pi against the learning-system repository working copy (the current working directory).

**Trigger routing (read first):**
- **"review" → review flow** (active track). Runs in the main session.
- **"teach me X" / "learn" / "study" → teaching loop** — use the `learning-teach` skill, NOT a review. "review" alone means the review flow.
- **"lesson" / "continue" → next curriculum lesson** — use the `learning-teach` skill.

**Position discipline (read first):** the current lesson/phase is **not** recorded in this skill. Derive it at runtime from `Learning System/CURRICULUM.md`, `Learning System/MISSION.md`, and the newest files in `Learning System/Lessons/` + `Learning System/Sessions/`. If those disagree, **STOP and report the contradiction to the user** before doing any work; do not guess or merge. (This repo has known stale statuses; treat the state files as the only source of position.)

**Turn tags (required — enforced by the gate):** begin every assistant message with `[[TURN:claims]]` (teaching/claims/plan), `[[TURN:quiz]]` (question batch), `[[TURN:grade]]` (grading a learner answer), or `[[TURN:none]]` (transitions/summaries). The gate strips the tag before the learner sees it and withholds a message whose tag is missing or unsupported by a matching, passing verification receipt.

## Context discipline (hard rules — read first)

Sessions die when the running conversation outgrows the model's context window: every tool output stays in the transcript forever. The fix is fewer, denser tool calls — not smaller messages.

- **Batch all reads.** Never chain multiple full-file reads for state. Use the batch tool ONCE (`python3 scripts/ops.py ...`, paths are repo-root-relative):
  - Session start: `python3 scripts/ops.py state <track>`
  - Any mix of ranges/tails/greps: `python3 scripts/ops.py bundle "PATH:N-M" "PATH:-N" "PATH@regex1|regex2"`
- **Read wiki pages by section.** First `bundle "Knowledge Wiki/wiki/<page>.md@^## "` to list headings, then fetch only the section you enrich.
- **Batch all writes.** Persistence at session end = ONE apply call, not N writes:
  `python3 scripts/ops.py apply <<'SPEC'` then a JSON spec, then `SPEC`.
  Spec: `{"writes":[{"path","content"}],"appends":[{"path","content"}],"replaces":[{"path","find","replace_with"}]}`.
- Target **≤12 tool calls per flow**. Never re-read a file already in context. Never dump whole files you only need one row of. For git, use `git diff --stat` (not a full diff) and `git diff -- <path>` only for a file you need; do not switch models mid-flow (it invalidates the prompt cache and re-bills the whole context).

## State files (relative to the working repository root)

- `Learning System/Core/💡 Learning Profile.md` — learner preferences. Read at session start.
- `Learning System/Core/📚 Active Concepts.md` — per-track concept rows with `Type` (`memory | concept | procedure | design`). Type drives scheduler intervals. Grep/range only the needed track — never the whole file; `📦 Concept Archive.md` is out of scope.
- `Learning System/Core/Attempts.json` — evidence-based mastery sidecar (attempt history, interval_index state machine, Feynman pass). Bundled by `ops.py state`; report via `ops.py mastery <track>` — **advisory only** (scores shown, not blocking).
- `Learning System/Core/Learner History.md` — compact tutor background (fuzzy/neutral/solid per concept, generated by `scripts/learner_history.py`). Read this for learner context — never grep `Archive/`.
- `Learning System/Core/🧯 Mistakes.md` — structured wrong-answer ledger (error_type + self-attribution). Due mistakes are priority-1 in the review queue.
- `Learning System/Core/📦 Concept Archive.md` — paused/archived concepts. **Do not grep** — out of scope. Search only on explicit revive request.
- `Learning System/Sessions/`, `Learning System/Reviews/`, `Learning System/Lessons/`, `Learning System/Learning Records/` — writes land here.
- `Learning System/MISSION.md`, `Learning System/CURRICULUM.md`, `Learning System/GLOSSARY.md`, `Learning System/RESOURCES.md` — mission, curriculum, glossary, curated readings. The curriculum source is **a source, not the source**; enrich from its Further Reading.

## Teaching flow (delegation) — Scout → Tutor → Clerk

Trigger: "teach me X", "lesson", or "continue". The pipeline runs in the **same pi session**, delegating to subagents.

0. **Scout (new lesson only):** if no `Learning System/Lessons/Lesson — <slug> — *.md` exists for the requested topic/lesson and no `.tmp/context-<session_id>-<slug>.json` (7-day TTL) is present, call the `scout` subagent first: `subagent({ agent: "scout", task: "<topic/lesson + why>" })`. Scout reads `MISSION.md`, `CURRICULUM.md`, `RESOURCES.md`, relevant Active Concepts rows, **and the curriculum source for the next lesson** — the live `phases/<phase>/<lesson>/docs/en.md` plus every URL in its `## Further Reading` (fetch loop: direct `curl -L --max-time 30` into `.tmp/`; PDFs → extract; YouTube → `yt-dlp --skip-download --write-auto-subs`; bot-blocked HTML → `curl https://r.jina.ai/<url>`; web search last). It hashes fetched bodies, compares to any prior digest hash, surfaces drift (`SCOUT DIGEST: ⚠️ Upstream changed`), and writes `Learning System/.tmp/context-<session_id>-<slug>.json` with `{goal, slug, tracks, concept_rows, prereqs, source_refs:[rohit_source, ...external_refs], rohit_hash, external_refs_hashes, failed_refs:[{url,reason}], lang_recommendation, fetched_at, roadmap_sha, synthesis}`. Every source/external ref carries `excerpt` (~500 chars) + `takeaways` + `adds_vs_rohit`; top-level `synthesis` is per-strand. Rohit = agenda, externals = enrichment. `prereqs` is load-bearing for the Tutor: `[{concept, keywords:[aliases/variants], why}]` covering every load-bearing dependency. Language per lesson `Languages:` header → `lang_recommendation` (Python / TypeScript / Rust). Scout posts a short `SCOUT DIGEST:` summary. The gate requires this digest for new lessons; resuming an existing `Lessons/` file bypasses it.
1. Load `Learning System/MISSION.md` + `Learning System/CURRICULUM.md` to determine the next lesson (or the requested topic) — derive position per the position discipline above. If resuming (`Lessons/` file exists), the lesson file + last `Sessions/` note are the source of truth — no Scout digest needed.
2. **`lesson`/`continue`:** pick the next lesson per `CURRICULUM.md` (sequential within a mission). If resumable, resume where left off. A `done` lesson is never re-taught — retrieval-verify instead.
3. **`teach me X`:** in current-mission scope → treat as a curriculum node; out of scope → one-off that still feeds Pending Ingest for Clerk, and surface the "switching focus?" question.
4. Delegate the full probe → plan → teach loop to the `learning-teach` skill. Claim verification runs via **foreground** `fact-check` subagents; question batches are audited via `quiz-audit` subagents before showing. The Tutor **does not** write wiki pages, Active Concepts rows, or any position/state file (MISSION/CURRICULUM/Profile/Mistakes) — it writes its four handoff artifacts (lesson file, session note, learning record, `Pending Ingest.json`) in one batch at pause/lesson-end and hands off to the `clerk` subagent, which reconciles state at `/ingest`.

## Review flow

Trigger: "review". **Run this review in the main session** (it is interactive). Grades are verified via foreground `grade-audit` subagents — do not bypass.

1. Track selection: `aiefs` / `aie` → the active track. If the user names an archived track, note it is archived and offer the active one. Neither → the active track.
2. Session start — ONE call: `python3 scripts/ops.py state <track>`. This returns Learning Profile + the track's Active Concepts rows + Attempts.json (advisory mastery) + 🧯 Mistakes.md. Do not read those files separately.
3. Build the queue:
   - Slots 1–2 = due mistakes from `🧯 Mistakes.md` where next retry ≤ today (`active`/`review`), oldest first (priority-1).
   - Remaining 3 slots = type-aware due reviews (Next Review ≤ today), shuffled. Adjacency constraint: no two consecutive concepts from the same Source (if impossible, shuffle anyway).
4. Per concept: one question, one answer (≤1 line), targeting the 20% insight worth 80%. Math (paper accommodation): ask for the final result computed on paper — "Work on paper, reply with just the final number / chosen letter (A–D)." Never require typing full LaTeX/formulas verbatim. Correct final answer validates formula recall — do not skip math concepts.
5. Question type alternation by Last Q Type: blank/definitional → discriminative; discriminative → definitional.
6. After each answer: grade pass/fail, then verify the grade with ONE **foreground** `grade-audit` subagent call before presenting it:
   `subagent({ agent: "grade-audit", task: {"gate":"grade_audit","concept":..,"question":..,"learner_answer":..,"claimed_verdict":"pass|fail","source_excerpt":..,"feynman_transcript":..} })`.
   **Grade turns take `grade_audit` ONLY — never `fact-check` for a grade.** If the verifier disagrees (`correct_verdict` differs), use its verdict. Then record via `python3 scripts/ops.py attempt "Concept" pass|fail [feynman_pass|feynman_fail]` — this updates Attempts.json (recency-weighted mastery 0–1, confidence cap {1:0.5, 2:0.8}, interval_index +1 on pass / +2 on 2 consecutive passes / −1 on fail, next_review). On fail also append a row to `🧯 Mistakes.md` with error_type (`structural|deviation|application|metacognitive`) and self-attribution; on next correct recall bump Retries, after 2 consecutive correct mark `graduated`. For `concept`/`design` types, elicit a Feynman explain-back (own words, when/why, nearest-neighbour distinction, one example) and pass `feynman_pass`/`feynman_fail` — score shown but **not blocking**. Then write `Reviews/Review — [Concept] — [Date].md` and update Active Concepts `last_reviewed`/`next_review` (from Attempts.json) / `Last Q Type`.
7. Cap 5. Then ask "Any you want to dig deeper on?" — if yes, deep-dive one concept.
8. Surface open questions from Active Concepts. Also surface the advisory mastery line for each concept (e.g. `mastery 0.50 — Feynman: —`) alongside Held/Advanced for calibration.
8b. **Review-session write audit (gate-enforced).** After the Review note(s), session note, and touched Active Concepts / Mistakes rows are written, dispatch ONE **foreground** `review-session-audit` on the exact writes (generation-to-emission, never a summary):
   `subagent({ agent: "review-session-audit", task: {"gate":"review_session","concepts":[...],"transcript":"exact Q/A + learner answers + claimed verdicts","grade_verdicts":[{"concept":..,"correct_verdict":"pass|fail"}, ...],"written_files":[{"path":"Learning System/Reviews/...","content":"exact written text"}, ...],"state_rows":"exact touched Active Concepts / Mistakes / Attempts text"} })`.
   The `learning-gate` arms this gate when the session note is written and withholds the closing summary until a receipt exists. `PASS`/`PASS_WITH_FLAGS` renders clean; `ISSUES` renders with a `⚠️ REVIEW FLAGS SURFACED` banner — never a withhold, never a re-run (hard cap **2 passes per flow**). Scope is fenced: findings in MISSION/CURRICULUM/Learning Profile/Learner History/`Knowledge Wiki/`/git are `context_notes`, never blocking issues. A verifier that flags only state drift the review did not write is not a reason to fix or re-run.
9. **State audit (automatic, before the commit):** run `python3 "$HOME/learning-pi/pi/audit_state.py" --root .` (read-only). Fix any error **or warning** this review touched using the `STATE_AUDIT_FIXES` hints, then re-run once; surface ambiguous hints-less warnings and unrelated drift without fixing. Report every ❌/⚠️ loudly, then commit state only (`Learning System/`, `Knowledge Wiki/`). On the final line, emit `STATE_AUDIT_VERDICT: {"errors":N,"warnings":M}`. The `learning-gate` extension surfaces a `⚠️ STATE AUDIT` banner when errors or warnings > 0. On-demand, the same script runs via `/audit` (report-only).

Intervals (type-aware): memory [0d,1d,3d,7d,14d,30d,60d] · concept [3d,7d,14d,30d] · procedure [3d,7d,14d] · design [14d,28d]. Mastery (advisory): memory/procedure quantitative; concept/design require Feynman pass.

## Ingest flow — via the clerk subagent (handoffs from Tutor and standalone `/ingest`)

Trigger: "ingest" with content to add (NOT a review). Delegate to the `clerk` subagent. Clerk reads `Pending Ingest.json` when the ingest originates from a lesson; standalone ingests pass the supplied content.

1. If `Learning System/Core/Pending Ingest.json` exists (lesson handoff), read it — it contains `{partial, status, resume_from, lesson_file, session_file, concepts, mistakes, source_url|source_file, created_at}` (`partial:true` for a `/pause` handoff, `partial:false` + `status:"done"` for a final lesson end). Use `lesson_file` as the source of content; `status`/`resume_from`/`concepts`/`mistakes` drive the state reconciliation in step 7b.
2. Otherwise extract concepts from the supplied content.
3. Overlap check — ONE bundle call with an alternation regex over candidate keywords: `python3 scripts/ops.py bundle "Learning System/Core/📚 Active Concepts.md@kw1|kw2|kw3"` (or `#^## <track>` for the full track section).
4. Overlap → enrich the existing wiki page + insight row with genuinely new details; set `last_reviewed` today; write the session note as enrichment (not new ingest). Read only the target page's relevant section (headings first via `@^## `).
5. No overlap → new concept: status `developing`, `last_reviewed` today, `next_review` +3d, `Last Q Type` `definitional`.
6. Outside focus area → ask about switching focus. Stagger schedules for multiple new concepts.
7. Persist EVERYTHING in one apply call (`ops.py apply` heredoc): wiki page(s), `index.md` update, `log.md` entry, session note.
7b. **Reconcile position state from the handoff** (lesson handoffs): use `Pending Ingest.json`'s `status`/`resume_from`/`concepts`/`mistakes` as the single source to align the position pointers in `MISSION.md`, the `CURRICULUM.md` row, `💡 Learning Profile.md` (Current Focus / Current Position), and the `📚 Active Concepts.md` track header. Add handoff `concepts` missing from Active Concepts as new rows (developing, today, +3d, definitional); append handoff `mistakes[]` to `🧯 Mistakes.md` with canonical concept names; sync touched Active Concepts `next_review`/`last_reviewed` from `Attempts.json`; run `scripts/learner_history.py`. Surface (don't merge) any disagreement with the lesson file. Keep these out of the review-gate `target_files` — the state audit covers them.
8. **Independent review gate (parent-owned).** Clerk does NOT run the gate. When Clerk returns its `CLERK_WRITES: {"wiki":[...],"state":[...],"concepts":[...],"commit":"..."}` receipt, the Tutor dispatches ONE **foreground** `review-gate` on the wiki pages Clerk wrote: `target_files:[{"path":"Knowledge Wiki/wiki/<page>.md"}, ...]` from `CLERK_WRITES.wiki` (omit `content`; the gate reads the files on disk), `out_of_scope` listing the state files, and `lesson_ref` when this came from a lesson. Fold its verdict. On high/medium target issues, re-dispatch Clerk with the fix (it writes + commits), then re-review once — **max 2 review cycles, never a third, and NEVER re-dispatch review-gate for state/bookkeeping drift** (findings in MISSION/CURRICULUM/Learning Profile/Learner History/Mistakes/Attempts/lesson/session/log/index are the state audit's job and are demoted to `context_notes`). Never hard-block on review flags: an `ISSUES`/`PASS_WITH_FLAGS` verdict is surfaced by the gate, not re-run.
9. **State audit** is run by Clerk before it returns (`python3 "$HOME/learning-pi/pi/audit_state.py" --root .`); it fixes the error **or warning** findings it touched using the `STATE_AUDIT_FIXES` hints, re-runs once, surfaces hint-less/unrelated findings, and reports `STATE_AUDIT_VERDICT: {"errors":N,"warnings":M}`. Fold that verbatim.
10. **Close:** if `Pending Ingest.json` has `partial:true` (a `/pause` handoff), ingest today's concepts and KEEP both the `.tmp/context-*.json` digest and the lesson `in-progress` (clear only the marker, commit + push) — the digest's 7-day TTL still applies. Only a final (non-partial) ingest deletes the consumed digest, clears the marker, and lets the curriculum row go `done`.
11. **Final summary:** your post-clerk ingest summary is a `[[TURN:none]]` turn — start it with the tag and fold in the Tutor's `REVIEW_GATE_VERDICT` and Clerk's `STATE_AUDIT_VERDICT` markers. An untagged summary after a clerk dispatch is treated as an implicit `[[TURN:none]]` (verified by the review receipt), but tag it anyway.

### Handwritten notes

If the source is an image (handwritten notes, photo of a page), transcribe it verbatim before extraction:

- Use a vision-capable model (attach the image to the main session) to read the image, or ask the user to provide the text.
- Transcribe verbatim preserving structure (headings, bullets, diagrams in brackets); light cleanup only (fix obvious spelling, expand unambiguous abbreviations like 'bc' → 'because'); no rephrasing, summarization, or interpretation.
- Retry once on failure; if still failing, tell the user — never silently skip the image.

## End-of-session writes

1. Update Active Concepts — statuses, dates, new concepts, open questions. Preserve existing rows.
2. On `consolidated`: move to `Archive/Consolidated/[concept].md` (name, date, insight, wiki link, related), remove from Active.
3. Write `Sessions/Session — [Topic] — [Date].md` (date, topic, concepts, statuses, open questions) with a one-line interleaving summary.
4. Consistency check — ONE bundle call re-grepping only the touched rows: `ops.py bundle "Learning System/Core/📚 Active Concepts.md@<concept1>|<concept2>" "Knowledge Wiki/index.md@<title>" "Knowledge Wiki/log.md:-3"`; verify today's `last_reviewed`, correct `next_review`, `Last Q Type`, all ingested concepts present, wiki pages in `index.md`, log entry present. Fix discrepancies in a single apply call. If the user claims stale dates are wrong, cross-check session notes.
5. Refresh learner context — run `python3 scripts/learner_history.py` (regenerates `Core/Learner History.md`).
6. Confirm completion — what was saved, what's due next.

## pi adaptation notes

- **Source of truth:** the repository working copy (current working directory). State lives in `Learning System/` and `Knowledge Wiki/`.
- **Pipeline:** `scout` → Tutor (main session) → `clerk`, all in one pi session. Scout writes the ephemeral digest; Tutor teaches; Clerk ingests. Never write wiki pages/Active Concepts from the Tutor.
- **Gate:** the `learning-gate` extension blocks unverified teaching/quiz/grade turns and enforces the Scout digest for new lessons. Fixed verifier wording lives in the verifier agent files — send data only.
- **State commits:** commit and push **state only** (`Learning System/`, `Knowledge Wiki/`) per `Learning System/AGENTS.md`. The pi control layer lives in a separate repository; do not commit it here.
