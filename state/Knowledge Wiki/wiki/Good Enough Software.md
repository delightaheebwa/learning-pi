# Good Enough Software

The principle that software doesn't need to be perfect — it needs to be **good enough**. Knowing when to stop is a critical skill.

## Core ideas

- **It will never be perfect**: Chasing perfection is infinite. Deliver value at the right threshold.
- **Involve users in defining "good enough"**: The people using the software should help decide what's acceptable. (Exception: life-critical systems like pacemakers, where you don't get to negotiate.)
- **Under-promise and over-deliver**: Work out what you can *reasonably* deliver, deliver it excellently, and then let users be pleasantly surprised. That's when you hear "it would be nice if..."
- **Know when to stop**: More features ≠ better software. Scope creep is the enemy of shipping.

## The psychology

People find it easier to get on board with an ongoing success. Show them a glimpse of the future (a working prototype, a tracer bullet), and they'll help you get there — rather than waiting for a perfect finished product that never arrives.
